# استقرار مستقل حاتم — وضعیت ۲۰۲۶/۰۹/۲۶

این مسیر مستقل از Cloudflare است: Node 24، SQLite با WAL و فایل‌های خصوصی در volume پایدار. برای استقرار اولیه تک‌سرور است؛ چند replica برنامه اجرا نکنید. نسخه نمایشی آنلاین به‌صورت خودکار با این تغییرات به‌روزرسانی نشده است.

## راه‌اندازی

1. Ubuntu Server 24.04 LTS amd64 نصب شود. با `sudo bash deploy/bootstrap-ubuntu.sh`، Docker رسمی و ابزارهای لازم نصب می‌شوند. اسکریپت عمداً Firewall را فعال نمی‌کند تا SSH سفارشی قطع نشود.
2. مسیر پروژه روی سرور `/opt/hatam` باشد و مالکیت آن به کاربر استقرار داده شود.
3. `deploy/env.template` به `deploy/.env` کپی و همه `CHANGE_ME`ها جایگزین شوند. سه Secret با `openssl rand -hex 32`، مستقل از هم تولید شوند. فایل `.env` هرگز Commit یا در چت ارسال نشود.
4. قبل از DNS، پورت صحیح SSH را در UFW مجاز کنید؛ سپس ۸۰ و ۴۴۳ را مجاز و Firewall را فعال کنید.
5. رکوردهای A جدول پایین به IP ثابت VPS اشاره کنند. اگر IPv6 روی سرور تنظیم نشده، رکورد AAAA نسازید.
6. از پوشه پروژه `bash deploy/release.sh` اجرا شود. این فرمان Preflight، Build، migration، اجرای سرویس‌ها و Health Check داخلی را انجام می‌دهد.
7. مهاجرت‌ها هنگام شروع، در یک تراکنش اجرا می‌شوند؛ تغییر محتوای مهاجرت اجراشده خطاست. داده Cloudflare خودکار منتقل نمی‌شود.
8. برای ایجاد اولین مدیر، متغیرهای خصوصی `HATAM_ADMIN_MOBILE` و `HATAM_ADMIN_PASSWORD` (حداقل ۱۲ کاراکتر) را موقتاً به محیط کانتینر بدهید و `node scripts/bootstrap-admin.mjs` را اجرا کنید. این ابزار هیچ حساب موجودی را بازنویسی نمی‌کند. سپس رمز bootstrap را از محیط حذف کنید. ورود مدیر در `/login/admin` با شماره و رمز انجام می‌شود.
9. `bash deploy/smoke-production.sh` باید برای تمام دامنه‌ها موفق شود؛ سپس ورود هر نقش، آپلود، چت/اعلان، OTP، پیامک و پرداخت آزمایشی دستی بررسی شود.

### ایجاد مدیر اولیه بدون درج رمز در فرمان

```bash
read -r -p "Admin mobile: " HATAM_ADMIN_MOBILE
read -r -s -p "Admin password: " HATAM_ADMIN_PASSWORD; echo
export HATAM_ADMIN_MOBILE HATAM_ADMIN_PASSWORD
docker compose --env-file deploy/.env -f deploy/compose.yml run --rm -e HATAM_ADMIN_MOBILE -e HATAM_ADMIN_PASSWORD app node scripts/bootstrap-admin.mjs
unset HATAM_ADMIN_MOBILE HATAM_ADMIN_PASSWORD
```

## دامنه‌های سرویس‌های پیامک و پرداخت

### دامنه‌های تأییدشده پروژه

برای نام‌های زیر رکورد A به IP سرور تنظیم شود. تا زمان تهیه VPS رکوردها تغییر نکنند. اگر IPv6 روی سرور فعال نیست، رکورد AAAA اشتباه ایجاد نشود.

| دامنه | مسیر شروع |
| --- | --- |
| hatamestate.com | / |
| web.hatamestate.com | /app |
| app.hatamestate.com | /app |
| admin.hatamestate.com | /admin |
| consultant.hatamestate.com | /consultant |
| agency.hatamestate.com | /agency |
| panel.hatamestate.com | /panel |
| www.hatamestate.com | انتقال دائمی به دامنه اصلی |

تنظیم Caddy برای این نام‌ها آماده شده ولی روی سرور واقعی آزمایش نشده است. مقدار APP_DOMAIN برابر hatamestate.com باشد. هر میزبان API هم‌مبدأ دارد. نشست‌ها host-only هستند: ورود به یک زیردامنه به معنی ورود خودکار به بقیه نیست. HTTPS و هدایت مسیر شروع برای تک‌تک میزبان‌ها باید بعد از اتصال DNS آزمایش شوند.

متغیر خصوصی سرور `INTEGRATION_ALLOWED_HOSTS` شامل نام دقیق دامنه‌های مورد اعتماد، جداشده با کاما است (بدون پروتکل، مسیر یا wildcard). دامنه API پیامک، درخواست و تأیید پرداخت و صفحه پرداخت را پس از تأیید سرویس‌دهنده وارد کنید. فهرست خالی ارسال را مسدود می‌کند؛ HTTPS روی پورت استاندارد اجباری است و ریدایرکت API دنبال نمی‌شود. افزودن سرویس جدید نیاز به تغییر کد ندارد، ولی دامنه جدید باید توسط مسئول سرور تأیید و سرویس مجدداً اجرا شود. URL و پترن و اطلاعات سرویس در ادمین مدیریت می‌شوند. فقط دامنه تحت کنترل سرویس‌دهنده معتبر را مجاز کنید؛ این فهرست جایگزین محدودیت خروجی شبکه برای IPهای خصوصی/متادیتا و کنترل DNS روی VPS نیست. این مرحله مسیرهای پیامک و پرداخت را پوشش می‌دهد؛ سایر اتصال‌ها همچنان نیازمند ممیزی‌اند.

## داده و بازگشت

دیتابیس، WAL و رسانه‌ها در volume `hatam-data` هستند. قبل از ارتقا سرویس‌های `app` و `reminders` را متوقف و از کل volume نسخه پشتیبان بگیرید؛ از فایل SQLite زنده به‌تنهایی کپی نکنید. نسخه قبلی image و نسخه هماهنگ داده برای بازگشت نگهداری شود. بازیابی ابتدا روی volume آزمایشی بررسی شود. کلید رمزگذاری تنظیمات را همراه بکاپ، جدا و امن نگهداری کنید.

- بکاپ فوری: `bash deploy/backup.sh /opt/hatam-backups`
- بازیابی تأییدشده: `bash deploy/restore.sh --confirm /opt/hatam-backups/hatam-data-....tar.gz`
- نصب بکاپ روزانه: فایل‌های `deploy/systemd/hatam-backup.*` را به `/etc/systemd/system/` کپی و با `systemctl enable --now hatam-backup.timer` فعال کنید.
- نگهداری پیش‌فرض ۱۴ روز است و با `HATAM_BACKUP_RETENTION_DAYS` تغییر می‌کند. نسخه خارج از سرور نیز باید به فضای امن دیگری منتقل شود.

## اطلاعات لازم برای شروع استقرار از راه دور

- IP عمومی VPS و پورت SSH
- نام کاربر SSH دارای `sudo`
- مسیر کلید خصوصی روی همین رایانه یا تأیید اینکه کلید در SSH Agent بارگذاری شده؛ کلید خصوصی/رمز را در چت نفرستید
- ایمیل دریافت هشدار گواهی SSL
- تأیید ایجاد رکوردهای DNS توسط مالک دامنه یا دسترسی محدود DNS

## موارد باز قبل از انتشار عملیاتی

- اجرای Docker/HTTPS روی سرور واقعی و آزمون بازیابی بکاپ هنوز انجام نشده است.
- اجرای ابزار اولین مدیر روی سرور و آزمون کامل دسترسی نقش‌ها؛ ابزار و آزمون پایه نشست‌ها آماده‌اند.
- انتقال/تطبیق داده و فایل‌های محیط قبلی، در صورت نیاز؛ شارژهای تاریخی که فقط دفتر تراکنش دارند نیازمند تطبیق دستی‌اند و خودکار دوباره شارژ نمی‌شوند.
- آزمون واقعی OTP، پیامک، درگاه منتخب و ارسال اعلان‌ها.
- بررسی وابستگی‌ها، کنترل درخواست‌های خارجی و آزمون بصری موبایل/دسکتاپ.
- آزمون HTTPS و مسیر شروع هفت دامنه بالا روی VPS؛ تنظیم محلی جایگزین آزمون آنلاین نیست.

این فایل اعلام اتمام تمام نقص‌های پروژه نیست؛ مراحل بالا دروازه‌های انتشار واقعی هستند.
